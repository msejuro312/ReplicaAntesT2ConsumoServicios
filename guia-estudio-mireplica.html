1. Introducción: qué es mi réplica y cómo funciona

Mi réplica reconstruye, creando los archivos a mano, los 2 proyectos del profe: la API REST (carpeta TEMA03) y el cliente MVC (carpeta TEMA03_CONSUMIR_SERVICIOS). Son una pareja (frontend + backend): la API es una Web API de ASP.NET Core 7 que habla con DB_BIBLIOTECA usando ADO.NET con procedimientos almacenados (sin ORM), y el cliente MVC consume esa API por HTTP con HttpClient. El cliente nunca toca la base de datos.

ProyectoQué esTecnologíaPuerto¿Toca la BD?
WebApi\WebApplication1API REST "de servicio"ASP.NET Core Web API (.NET 7)https://localhost:7229Sí — ejecuta los SPs de DB_BIBLIOTECA
ConsumoServicios\WebApplication1Cliente MVC que "consume servicios"ASP.NET Core MVC (.NET 7)http://localhost:5217No — le pide los datos a la API

El flujo completo (de arriba hacia abajo)

Navegador (usuario) | | GET http://localhost:5217/Autor v [1] CLIENTE MVC (ConsumoServicios) --> AutorController.Index() | NO toca la base de datos | usa HttpClient con apiBase = "https://localhost:7229" | GET https://localhost:7229/api/Autor v [2] API REST (WebApi) --> AutorController.Get() --> AutorService.list() | inyección de dependencias (IAutorService) | ADO.NET: SqlConnection + SqlCommand + CommandType.StoredProcedure v [3] SQL Server --> EXEC sp_list_autores (sobre DB_BIBLIOTECA) ^ | respuesta: filas (AutorId, Nombre) | la API las devuelve como JSON | el cliente las deserializa a List<Autor> y las pinta en una tabla
Regla del puerto (documentada): la API queda en https://localhost:7229 y el cliente usa apiBase = "https://localhost:7229". El puerto HTTPS de la API siempre debe coincidir con el apiBase del cliente. El puerto del cliente (5217) es independiente: solo es la dirección donde navega el usuario.

2. Requisitos previos: SQL Server, SSMS, .NET 7 y Visual Studio

  • SQL Server corriendo en la máquina (el proyecto usa server=., instancia local).
  • SQL Server Management Studio (SSMS) para revisar la base DB_BIBLIOTECA.
  • .NET 7 SDK/Runtime. En mi máquina está el SDK 10.0.302 con runtimes 7.0.20 / 8.0.29 / 10.0.10, y dotnet new webapi -f net7.0 funciona sin problema.
  • Visual Studio 2022 con la carga de trabajo "ASP.NET y desarrollo web".
La cadena de conexión es un requisito de la BD: la API lee de appsettings.json esta cadena: Server=.;Database=DB_BIBLIOTECA;Integrated Security=True;TrustServerCertificate=True; En este PC usó autenticación de Windows (Integrated Security=True, sin usuario ni password). La versión anterior con user=sa;password=sql quedó comentada con // en el archivo.
Certificado HTTPS de desarrollo: para que Swagger y el futuro cliente llamen a https://localhost:7229 sin problemas, ejecuta una vez: dotnet dev-certs https --trust.
Comprobación rápida de la BD: desde SSMS (o sqlcmd) verifico que exista DB_BIBLIOTECA con las tablas Autor y Libro y los 6 SPs, antes de levantar la API.

3. Paso 0: La base de datos DB_BIBLIOTECA (ya creada con el script del profe)

Para esta réplica NO creo la base de nuevo: ya la había creado antes ejecutando el script Query_Biblioteca(1).sql de ReposProfe (el código íntegro del script está documentado en mi otra guía: guia-estudio-reposprofe.html).

Estado actual de la base (verificado con sqlcmd):

  • Tabla Autor: AutorId INT IDENTITY PK, Nombre, Nacionalidad. Contiene 2 autores (id 1 García Márquez, id 2 Vargas Llosa).
  • Tabla Libro: LibroId INT IDENTITY PK, AutorId FK, Titulo, ISBN UNIQUE, AnioPublicacion. Contiene los libros de prueba y los que inserté al probar la API.
  • 6 procedimientos almacenados: sp_list_autores, sp_list_libros, sp_find_libro_by_id, sp_insert_libro, sp_update_libro, sp_delete_libro.

Los 6 SPs y cómo los usa la API

SPQué haceSe usa en…

sp_list_librosLista libros con nombre del autor (JOIN)LibroService.list() → GET api/Libro

Dato clave: la API nunca escribe SQL a mano: crea un SqlCommand con el nombre del SP y CommandType.StoredProcedure. El sp_list_autores devuelve solo 2 columnas (AutorId, Nombre), por eso el servicio solo mapea esas 2.

4. LA API REST (MiReplica\WebApi\WebApplication1)

Esta es la parte central de la guía. El orden de creación importa: los archivos dependen unos de otros, así que los creo en el orden que marca la dependencia (primero lo que no depende de nadie, y Program.cs al final porque depende de todas las piezas).

4.1. Crear el proyecto y agregar los paquetes NuGet (desde Visual Studio)

El proyecto lo creé con el CLI de .NET (con target explícito net7.0):

dotnet new webapi -n WebApplication1 -f net7.0 -o WebApplication1

Después lo abrí en Visual Studio y agregué los paquetes desde el Administrador de paquetes NuGet (clic derecho en el proyecto → Administrar paquetes NuGet → pestaña Examinar → buscar → Instalar):

¿Por qué Microsoft.Data.SqlClient? Es la librería moderna de ADO.NET para SQL Server. Sin ella no existen SqlConnection ni SqlCommand y el código de los Services no compila.

4.2. appsettings.json (la cadena de conexión)

Agrego la sección ConnectionStrings con la clave conexion (el nombre que leo después en los Services) usando autenticación de Windows y dejando la versión con sa comentada:

appsettings.json 
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  "ConnectionStrings": {
    "conexion": "Server=.;Database=DB_BIBLIOTECA;Integrated Security=True;TrustServerCertificate=True;",
    //"conexion": "server=.;database=DB_BIBLIOTECA;user=sa;password=sql;TrustServerCertificate=True;"
  }
}
Comentarios en JSON: aunque el JSON puro no admite comentarios, el proveedor de configuración de .NET usa JsonCommentHandling.Skip y los ignora, así que la línea //... no rompe la lectura. Integrated Security=True hace que SQL Server use el usuario de Windows de la sesión actual.

¡Error que me costó entender: "The Autor field is required"! La propiedad Autor de Libro es un string no anulable. 4.5. Services: AutorService, LibroService (ADO.NET + SPs)

Aquí está toda la lógica de base de datos. Para crear los servicios usé el truco de Visual Studio: escribo public class LibroService : ILibroService y, con el cursor sobre la interfaz, presiono Alt + Enter y elijo "Implementar interfaz". VS genera los métodos vacíos y solo me queda llenarlos.

Cómo se lee la cadena de conexión

Ambos servicios reciben IConfiguration por constructor y guardan la cadena en un campo:

private readonly string? conexion;

public AutorService(IConfiguration configuration)
{
    conexion = configuration.GetConnectionString("conexion");
}

AutorService.list(): el patrón "List temporal + while(reader.Read())"

Services/AutorService.cs 
using Microsoft.Data.SqlClient;
using WebApplication1.Interfaces;
using WebApplication1.Models;

namespace WebApplication1.Services
{
    public class AutorService : IAutorService
    {
        private readonly string? conexion;

        public AutorService(IConfiguration configuration)
        {
            conexion = configuration.GetConnectionString("conexion");
        }

        public List<Autor> list()
        {
            List<Autor> temporal = new List<Autor>();

            using (SqlConnection con = new SqlConnection(conexion))
            {
                using (SqlCommand command = new SqlCommand("sp_list_autores", con))
                {
                    command.CommandType = System.Data.CommandType.StoredProcedure;
                    con.Open();
                    using (SqlDataReader reader = command.ExecuteReader())
                    {
                        while (reader.Read())
                        {
                            Autor autor = new Autor
                            {
                                AutorId = reader.GetInt32(0),
                                Nombre = reader.GetString(1),
                            };
                            temporal.Add(autor);
                        }
                    }
                }
            }
            return temporal;
        }
    }
}
¿Por qué una lista temporal? Para las consultas de lectura (list) creo una List vacía y la lleno fila por fila con while (reader.Read()). Uso ExecuteReader porque espero un conjunto de filas de vuelta. reader.GetInt32(0) lee la columna 0 (AutorId) y reader.GetString(1) la columna 1 (Nombre), en el orden que devuelve el SP.

LibroService: los 5 métodos (con el detalle de cada patrón)

Services/LibroService.cs 
using Microsoft.Data.SqlClient;
using WebApplication1.Interfaces;
using WebApplication1.Models;

namespace WebApplication1.Services
{
    public class LibroService : ILibroService
    {
        private readonly string? conexion;

        public LibroService(IConfiguration configuration)
        {
            conexion = configuration.GetConnectionString("conexion");
        }

        // list(): mismo patrón que AutorService, pero el SP devuelve 5 columnas
        public List<Libro> list()
        {
            List<Libro> temporal = new List<Libro>();

            using (SqlConnection con = new SqlConnection(conexion))
            {
                using (SqlCommand command = new SqlCommand("sp_list_libros", con))
                {
                    command.CommandType = System.Data.CommandType.StoredProcedure;
                    con.Open();
                    using (SqlDataReader reader = command.ExecuteReader())
                    {
                        while (reader.Read())
                        {
                            Libro libro = new Libro
                            {
                                LibroId = reader.GetInt32(0),
                                Titulo = reader.GetString(1),
                                ISBN = reader.GetString(2),
                                AnioPublicacion = reader.GetInt32(3),
                                Autor = reader.GetString(4),
                            };
                            temporal.Add(libro);
                        }
                    }
                }
            }
            return temporal;
        }

        // getById(): libro = null → el controller responde 404 si no encontró filas
        public Libro getById(int LibroId)
        {
            Libro libro = null;

            using (SqlConnection con = new SqlConnection(conexion))
            {
                using (SqlCommand command = new SqlCommand("sp_find_libro_by_id", con))
                {
                    command.CommandType = System.Data.CommandType.StoredProcedure;
                    command.Parameters.AddWithValue("@LibroId", LibroId);
                    con.Open();
                    using (SqlDataReader reader = command.ExecuteReader())
                    {
                        while (reader.Read())
                        {
                            libro = new Libro
                            {
                                LibroId = reader.GetInt32(0),
                                Titulo = reader.GetString(1),
                                ISBN = reader.GetString(2),
                                AnioPublicacion = reader.GetInt32(3),
                                Autor = reader.GetString(4),
                            };
                        }
                    }
                }
            }
            return libro;
        }

        // insert/update/delete: bool resp = false + ExecuteNonQuery() > 0 + transacción
        public bool insert(Libro libro)
        {
            bool resp = false;

            using (SqlConnection con = new SqlConnection(conexion))
            {
                con.Open();
                SqlTransaction tran = con.BeginTransaction();
                try
                {
                    using (SqlCommand command = new SqlCommand("sp_insert_libro", con))
                    {
                        command.Transaction = tran;
                        command.CommandType = System.Data.CommandType.StoredProcedure;
                        command.Parameters.AddWithValue("@AutorId", libro.AutorId);
                        command.Parameters.AddWithValue("@Titulo", libro.Titulo);
                        command.Parameters.AddWithValue("@ISBN", libro.ISBN);
                        command.Parameters.AddWithValue("@AnioPublicacion", libro.AnioPublicacion);
                        resp = command.ExecuteNonQuery() > 0;
                        tran.Commit();
                    }
                }
                catch (Exception ex)
                {
                    tran.Rollback();
                }
            }
            return resp;
        }

        public bool update(Libro libro)
        {
            bool resp = false;

            using (SqlConnection con = new SqlConnection(conexion))
            {
                con.Open();
                SqlTransaction tran = con.BeginTransaction();
                try
                {
                    using (SqlCommand command = new SqlCommand("sp_update_libro", con))
                    {
                        command.Transaction = tran;
                        command.CommandType = System.Data.CommandType.StoredProcedure;
                        command.Parameters.AddWithValue("@LibroId", libro.LibroId);
                        command.Parameters.AddWithValue("@AutorId", libro.AutorId);
                        command.Parameters.AddWithValue("@Titulo", libro.Titulo);
                        command.Parameters.AddWithValue("@ISBN", libro.ISBN);
                        command.Parameters.AddWithValue("@AnioPublicacion", libro.AnioPublicacion);
                        resp = command.ExecuteNonQuery() > 0;
                        tran.Commit();
                    }
                }
                catch (Exception ex)
                {
                    tran.Rollback();
                }
            }
            return resp;
        }

        public bool delete(int LibroId)
        {
            bool resp = false;

            using (SqlConnection con = new SqlConnection(conexion))
            {
                con.Open();
                SqlTransaction tran = con.BeginTransaction();
                try
                {
                    using (SqlCommand command = new SqlCommand("sp_delete_libro", con))
                    {
                        command.Transaction = tran;
                        command.CommandType = System.Data.CommandType.StoredProcedure;
                        command.Parameters.AddWithValue("@LibroId", LibroId);
                        resp = command.ExecuteNonQuery() > 0;
                        tran.Commit();
                    }
                }
                catch (Exception ex)
                {
                    tran.Rollback();
                }
            }
            return resp;
        }
    }
}
Resumen de los 3 patrones de Service:
  • list() → ExecuteReader + List temporal que se llena en while (reader.Read()).
  • getById() → ExecuteReader, pero inicializo libro = null: si el SP no devuelve filas, queda null y el controller responde 404. Obligatorio pasar el parámetro @LibroId.
  • insert/update/delete → bool resp = false, ExecuteNonQuery() > 0 devuelve cuántas filas afectó (1 si funcionó), y todo va dentro de una transacción (BeginTransaction + Commit/Rollback). Para escritura se usa ExecuteNonQuery, no ExecuteReader.
Dos errores que tuve en los Services:
  1. En getById olvidé command.Parameters.AddWithValue("@LibroId", LibroId) → la API devolvía 500 con el error "Procedure expects parameter '@LibroId'".
  2. Puse using System.Windows.Input; (un namespace de WPF, no existe en un proyecto Web) → error de compilación. En web se usa Microsoft.Data.SqlClient.

4.6. Controllers: AutorController, LibroController

Los controladores exponen los endpoints HTTP, llaman al servicio (vía interfaz) y forman la respuesta con ApiResponse<T>. Nota: AutorController responde la lista "cruda" (sin ApiResponse), y LibroController sí envuelve las respuestas de los casos especiales.

Controllers/AutorController.cs 
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Mvc;
using WebApplication1.Interfaces;

namespace WebApplication1.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class AutorController : ControllerBase
    {
        private readonly IAutorService _service;

        public AutorController(IAutorService service)
        {
            _service = service;
        }

        [HttpGet]
        public async Task<IActionResult> Get()
        {
            var autores = _service.list();
            return Ok(await Task.Run(() => autores));
        }
    }
}
Controllers/LibroController.cs 
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Mvc;
using WebApplication1.Interfaces;
using WebApplication1.Models;

namespace WebApplication1.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class LibroController : ControllerBase
    {
        private readonly ILibroService _service;

        public LibroController(ILibroService service)
        {
            _service = service;
        }

        [HttpGet]
        public async Task<IActionResult> Get()
        {
            var libros = _service.list();
            return Ok(await Task.Run(() => libros));
        }

        [HttpGet("{LibroId}")]
        public async Task<IActionResult> GetById(int LibroId)
        {
            var libro = _service.getById(LibroId);
            if (libro == null)
            {
                return NotFound(new ApiResponse<object>
                {
                    message = "No se encontró el libro con el id " + LibroId,
                    success = false,
                    data = ""
                });
            }
            else
            {
                return Ok(new ApiResponse<Libro>
                {
                    message = "Libro encontrado!",
                    success = true,
                    data = libro
                });
            }
        }

        [HttpPost]
        public async Task<IActionResult> Post([FromBody] Libro libro)
        {
            bool resp = _service.insert(libro);
            if (resp)
            {
                return Ok(new ApiResponse<Libro>
                {
                    message = "Libro insertado correctamente!",
                    success = true,
                    data = libro
                });
            }
            else
            {
                return BadRequest(new ApiResponse<object>
                {
                    message = "No se registró libro!",
                    success = false,
                    data = ""
                });
            }
        }

        [HttpPut]
        public async Task<IActionResult> Put([FromBody] Libro libro)
        {
            Libro lib = _service.getById(libro.LibroId);
            if (lib == null)
            {
                return NotFound(new ApiResponse<object>
                {
                    message = "No se encontró libro para actualizar!",
                    success = false,
                    data = ""
                });
            }
            else
            {
                bool resp = _service.update(libro);
                if (resp)
                {
                    return Ok(new ApiResponse<Libro>
                    {
                        message = "Libro actualizado correctamente!",
                        success = true,
                        data = libro
                    });
                }
                else
                {
                    return BadRequest(new ApiResponse<object>
                    {
                        message = "Ocurrió un error al actualizar libro!",
                        success = false,
                        data = ""
                    });
                }
            }
        }

        [HttpDelete("{LibroId}")]
        public async Task<IActionResult> Delete(int LibroId)
        {
            Libro lib = _service.getById(LibroId);
            if (lib == null)
            {
                return NotFound(new ApiResponse<object>
                {
                    message = "No se encontró libro para eliminar!",
                    success = false,
                    data = ""
                });
            }
            else
            {
                bool resp = _service.delete(LibroId);
                if (resp)
                {
                    return Ok(new ApiResponse<Libro>
                    {
                        message = "Libro eliminado correctamente!",
                        success = true,
                        data = lib
                    });
                }
                else
                {
                    return BadRequest(new ApiResponse<object>
                    {
                        message = "Ocurrió un error al eliminar libro!",
                        success = false,
                        data = ""
                    });
                }
            }
        }
    }
}
Patrón de los controllers: primero valido la existencia con getById (si null → NotFound con mensaje), luego ejecuto la operación y devuelvo Ok o BadRequest según el bool que devuelve el service.
Diferencia clave del PUT: [HttpPut] sin {LibroId}. El id llega en el body. (Lo escribí mal primero con [HttpPut("{LibroId}")] y Swagger mostraba un parámetro extra en la URL.)

5.4. Controllers/AutorController.cs (el consumidor con HttpClient)

Este es el corazón del cliente. Aquí está la regla del puerto aplicada: apiBase = "https://localhost:7229". El controller inyecta HttpClient, hace GET a api/Autor y deserializa la respuesta.

Controllers/AutorController.cs (cliente) 
using Microsoft.AspNetCore.Mvc;
using Newtonsoft.Json;
using WebApplication1.Models;

namespace WebApplication1.Controllers
{
    public class AutorController : Controller
    {
        private readonly HttpClient _httpClient;
        private readonly string apiBase = "https://localhost:7229";

        public AutorController(HttpClient httpClient)
        {
            _httpClient = httpClient;
            _httpClient.BaseAddress = new Uri(apiBase);
        }

        public async Task<IActionResult> Index()
        {
            var resp = await _httpClient.GetAsync("api/Autor");
            var contenido = resp.Content.ReadAsStringAsync().Result;
            List<Autor> lista = JsonConvert.DeserializeObject<List<Autor>>(contenido);
            return View(await Task.Run(() => lista));
        }
    }
}
Paso a paso del consumo: (1) BaseAddress apunta a la API; (2) GetAsync("api/Autor") hace la llamada HTTP a https://localhost:7229/api/Autor; (3) ReadAsStringAsync lee el body como texto (JSON); (4) JsonConvert.DeserializeObject<List<Autor>> convierte el JSON en una lista de objetos; (5) View(lista) pasa esa lista a la vista.

5.4b. Controllers/LibroController.cs (el CRUD completo con HttpClient)

Agregado hoy (08/08): es el mismo patrón de AutorController, pero ahora el cliente también puede crear y editar libros. Usa helpers privados (listLibros, getLibro, listAutores, insertar, actualizar) para no repetir el código HTTP, un SelectList de autores para los formularios y TempData["message"] para mostrar el mensaje de la API después del redirect.

Controllers/LibroController.cs (cliente) 
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Rendering;
using Newtonsoft.Json;
using System.Text;
using WebApplication1.Models;

namespace WebApplication1.Controllers
{
    public class LibroController : Controller
    {
        private readonly HttpClient _httpClient;
        private readonly string apiBase = "https://localhost:7229";
        public LibroController(HttpClient httpClient
            ) {
            _httpClient = httpClient;
            _httpClient.BaseAddress = new Uri(apiBase);


        }

        Task<List<Libro>> listLibros()
        {
            var response = await _httpClient.GetAsync("api/Libro");
            var content = await response.Content.ReadAsStringAsync();
            var lista = JsonConvert.DeserializeObject<List<Libro>>(content) ?? new List<Libro>();
            return await Task.Run(() => lista);
        }

        Task<Libro> getLibro(int LibroId)
        {
            var response = await _httpClient.GetAsync("api/Libro/" + LibroId);
            var content = await response.Content.ReadAsStringAsync();
            var apiResponse = JsonConvert.DeserializeObject<ApiResponse<Libro>>(content) ?? new ApiResponse<Libro>();
            var libro = apiResponse.data;
            return await Task.Run(() => libro);
        }

        Task<List<Autor>> listAutores()
        {
            var response = await _httpClient.GetAsync("api/Autor");
            var content = await response.Content.ReadAsStringAsync();
            var lista = JsonConvert.DeserializeObject<List<Autor>>(content) ?? new List<Autor>();
            return await Task.Run(() => lista);
        }

        Task<string> insertar(Libro libro)
        {
            var json = JsonConvert.SerializeObject(libro);
            var body = new StringContent(json, Encoding.UTF8, "application/json");
            var request = await _httpClient.PostAsync("api/Libro", body);
            var response = await request.Content.ReadAsStringAsync();
            var apiResponse = JsonConvert.DeserializeObject<ApiResponse<object>>(response) ?? new ApiResponse<object>();
            var message = apiResponse.message;
            return await Task.Run(() => message);
        }

        Task<string> actualizar(Libro libro)
        {
            var json = JsonConvert.SerializeObject(libro);
            var body = new StringContent(json, Encoding.UTF8, "application/json");
            var request = await _httpClient.PutAsync("api/Libro", body);
            var response = await request.Content.ReadAsStringAsync();
            var apiResponse = JsonConvert.DeserializeObject<ApiResponse<object>>(response) ?? new ApiResponse<object>();
            var message = apiResponse.message;
            return await Task.Run(() => message);
        }

        [HttpGet]

        public async Task<IActionResult> Index()
        {
            var lista = await listLibros();
            return View(lista);
        }

        [HttpGet]

        public async Task<IActionResult> Create()
        {
            var autores = await listAutores();
            ViewBag.autores = new SelectList(autores, "AutorId", "Nombre");
            return View(new Libro());

        }

        [HttpPost]

        public async Task<IActionResult> Create(Libro libro)
        {
            var message = await insertar(libro);
            TempData["message"] = message;
            return RedirectToAction("Index");
        }

        [HttpGet]

        public async Task<IActionResult> Edit(int LibroId)
        {
            var libro = await getLibro(LibroId);
            if (libro == null)
            {
                TempData["message"] = "El libro a editar no existe!";
                return RedirectToAction("Index");


            }
            else {
                var autores = await listAutores();
                ViewBag.autores = new SelectList(autores, "AutorId", "Nombre", libro.AutorId);
                return View(libro);

            }
        }

        [HttpPost]

        public async Task<IActionResult> Edit(Libro libro)
        { 
            var message = await actualizar(libro);
            TempData["message"] = message;
            return RedirectToAction("Index");
        }
    }
}
Claves de este controller:
  • SelectList(autores, "AutorId", "Nombre") llena el <select> de la vista con los autores traídos de api/Autor (en Edit pasa un 4º parámetro: el AutorId seleccionado).
  • TempData["message"] guarda el mensaje que devuelve la API (message) y la vista Index.cshtml lo muestra con @TempData["message"].
  • Solo tiene Index, Create y Edit. No hay Delete ni Details: los enlaces de la vista a Details/Delete fallan (404) y el Delete del libro no está implementado en el cliente.

5.7. Cómo se conectan los 2 proyectos y la prueba integrada

Para que la página del cliente muestre los autores y libros, primero debe estar corriendo la API (en https://localhost:7229). El orden de ejecución importa:

  1. Levantar la API: F5 en WebApi\WebApplication1 (perfil https). Queda en https://localhost:7229/swagger.
  2. Levantar el cliente: F5 en ConsumoServicios\WebApplication1. Abre http://localhost:5217.
  3. Navegar a http://localhost:5217/Autor: el controller hace GET https://localhost:7229/api/Autor y la vista pinta la tabla con los autores de DB_BIBLIOTECA.
  4. Navegar a http://localhost:5217/Libro (agregado hoy): LibroController.Index() consume GET https://localhost:7229/api/Libro y muestra el CRUD: Create New inserta y Edit actualiza (ambos usando ViewBag.autores y TempData["message"]).
Prueba integrada manual (equivalente en el navegador):
Con la API y el cliente corriendo, abro http://localhost:5217/Autor y verifico que la tabla muestre:
1 — García Márquez  |  2 — Vargas Llosa.
Luego http://localhost:5217/Libro: lista de libros, y pruebo Create New y Edit; al final veo el mensaje de la API en @TempData["message"].
Error típico de conexión: si el cliente sale con error "The SSL connection could not be established" o certificate validation, es el certificado de desarrollo. Solución: ejecutar una vez dotnet dev-certs https --trust. También verifica que la API esté corriendo y que apiBase coincida con el puerto HTTPS real de la API (regla del puerto).

6. Errores reales que resolví (para no volver a tropezar)

Estos son los errores que me aparecieron durante la réplica y cómo los resolví:

#SíntomaCausaSolución
1 Error de compilación en la interfaz delete(Libro libro) en vez de delete(int LibroId) Cambiar la firma de ILibroService a bool delete(int LibroId) y el controller llama _service.delete(LibroId)
2 Error de compilación: no encuentra la interfaz El service no tenía public class AutorService : IAutorService ni el using WebApplication1.Interfaces; Agregar la herencia : IAutorService y el using
3 Error de compilación CS0246 (System.Windows.Input) Puse un using System.Windows.Input; que no existe en proyectos Web (es de WPF) Eliminarlo; en Web uso Microsoft.Data.SqlClient
4 Swagger mostraba la ruta con un parámetro extra en el PUT Usé [HttpPut("{LibroId}")] y el id iba en la URL Cambiar a [HttpPut] sin segmento; el libroId va en el body
5 HTTP 500 en GET api/Libro/1: "Procedure expects parameter '@LibroId'" En getById faltaba command.Parameters.AddWithValue("@LibroId", LibroId); Agregar el parámetro antes de con.Open()
6 HTTP 400 en POST api/Libro: "The Autor field is required" La propiedad Autor es string no anulable y [ApiController] la valida como obligatoria Incluir "autor" en el JSON del body (aunque el SP no lo use)
7 Al presionar F5 se abría el perfil equivocado No había perfil activo definido En WebApplication1.csproj.user puse <ActiveDebugProfile>https</ActiveDebugProfile>
8 Le puse Microsoft.Data.SqlClient al cliente MVC (de costumbre, porque la API lo usa) El cliente no toca SQL Server: solo consume la API por HTTP con HttpClient Quitar el paquete del cliente; el SqlClient es exclusivo de la WebApi. En su lugar el cliente usa Newtonsoft.Json
9 El cliente no veía los datos (tabla vacía o error de conexión) Faltaba levantar la API, o el apiBase no coincidía con el puerto HTTPS de la API, o el certificado dev no era confiable Levantar primero la API; apiBase = "https://localhost:7229" (regla del puerto); dotnet dev-certs https --trust
Regla de oro aprendida: cuando un SqlCommand ejecuta un SP que recibe parámetros, siempre hay que agregar AddWithValue por cada @parametro que el SP espere. Si falta uno, SQL Server lanza error y la API responde 500.
Recuerda: el orden de las columnas que lee reader.GetInt32(0), GetString(1), etc., es el orden del SELECT del SP. Si cambio el SP o la vista, debo verificar ese orden.

7. Resumen: orden completo de creación y ejecución

Este es el orden que seguí (primero lo que no depende de nada, Program.cs al final):

Proyecto 1: la API (WebApi\WebApplication1)

  1. Crear el proyecto: dotnet new webapi -n WebApplication1 -f net7.0
  2. Paquetes NuGet (via VS): Microsoft.Data.SqlClient 5.2.0 (+ Swashbuckle que ya viene)
  3. appsettings.json → cadena conexion
  4. Models (Autor, Libro, ApiResponse<T>) → no dependen de nadie
  5. Interfaces (IAutorService, ILibroService) → dependen de Models
  6. Services (AutorService, LibroService) → dependen de Models + Interfaces; usar Alt+Enter → Implementar interfaz
  7. Controllers (AutorController, LibroController) → dependen de Interfaces + Models
  8. Program.cs → al final (usa Interfaces y Services en el AddScoped)
  9. launchSettings.json → perfil https activo en https://localhost:7229
  10. Compilar (dotnet build) y ejecutar (F5 → Swagger en https://localhost:7229/swagger)
  11. Probar los 6 endpoints en Swagger (y verificar en la base con sqlcmd)

Proyecto 2: el cliente (ConsumoServicios\WebApplication1)

  1. Crear el proyecto: dotnet new mvc -n WebApplication1 -f net7.0
  2. Paquete NuGet (via VS): Newtonsoft.Json 13.0.1 (no SqlClient)
  3. Program.cs → agregar AddHttpClient()
  4. Models (Autor, Libro, ApiResponse<T>) → copiados de la API
  5. Controllers/AutorController.cs → apiBase = "https://localhost:7229"
  6. Controllers/LibroController.cs (hoy) → CRUD de libros con HttpClient + SelectList y TempData
  7. Views/Autor/Index.cshtml → tabla con IEnumerable<Autor>
  8. Views/Libro/Index, Create y Edit (hoy) → generadas con el scaffolding (package CodeGeneration.Design)
  9. launchSettings.json → http://localhost:5217
  10. Ejecutar la prueba integrada: API en 7229 + cliente en http://localhost:5217/Autor y /Libro
⇩
Regla del puerto (una vez más): la API queda en https://localhost:7229 y el cliente usa apiBase = "https://localhost:7229". Si cambio el puerto HTTPS de la API, debo cambiar el apiBase del cliente.
